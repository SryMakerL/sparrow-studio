# Sparrow Studio WinForms preview

Windows x64 / .NET Framework 4.7.2 / C# 7.3. A reusable offline WebView2 preview over the existing SparrowStudio.Core native session, not a React/WASM host.

```csharp
using (var dialog = new SparrowStudio.WinForms.NestingPreviewDialog(job))
{
    // Optional, before ShowDialog: dialog.UserDataFolder = writableProfileDirectory;
    if (dialog.ShowDialog(owner) == DialogResult.OK)
    {
        var result = dialog.Result; // host-owned, independently validated, fully placed
        var validation = new NestingSolver().Validate(dialog.EffectiveJob, result);
        // EffectiveJob is a deep-cloned snapshot of the actual solve job, including selected budgets.
    }
}
```

Open the dialog, click Start, inspect Best / Current round, then Apply result. The separate ‘截止并保留当前轮’ (stop) command deep-clones the latest real current-round snapshot, requests cooperative native cancellation, awaits native exit and independently validates that frozen snapshot. It never selects global best or automatically commits. Candidate events cannot replace true current-round events; single-board candidate fallback is used only before any current-round event. After inspection, explicit ‘应用当前轮结果’ returns Reason=UserStopped, Cancelled=false, StoppedByUser=true and ResultSelection=CurrentRound. This is an already non-cancelled snapshot selected before cancellation, not a relabelled cancelled solve result. Incomplete snapshots remain visible with the missing count but cannot apply; all original quantities, per-board coverage and geometry checks remain required. Cancel or close overrides stop and discards approval, including while validation is pending.

The UI distinguishes 正在截止, 已截止待应用 and 截止快照未完整不可应用. Stop is disabled without a current snapshot; late events cannot overwrite the frozen snapshot. Before the single-use Start, budget controls are editable: total seconds entered directly as any whole number 1..600 (default 30), or left empty for automatic (null), initial search 0.1..600 seconds (step 0.1, default 2.5), insertion and compression 1..600 whole seconds (existing job values or 1), and advanced insertion failures 1..100 (existing value or 1; a count, not time). Initial total and existing phase values come from the caller job; unchanged 30-second smoke/ImageAssist jobs keep their original effective defaults. All controls remain disabled during and after the run; there is no persistence or rerun. Every board shares the same global budget: phase budgets are not added together. Initial construction observes cooperative deadlines. Automatic mode has no total deadline and its final-board compression window is compression seconds × insertion failures; with a total deadline, the final board keeps compressing for all remaining global time. Stop can end that wait early. Cancellation and window close never apply a candidate. Closing during a solve cancels and awaits native termination; it does not kill the solver. Failure is visible in the page (or a native initialization message) and the window remains closable. Current round and best are only actual native snapshots; there is no simulated motion or second polling consumer.

## Build and direct references

`dotnet build SparrowStudio.WinForms.csproj -c Release` produces `../dist/WinForms/Release`. Reference SparrowStudio.WinForms.dll, SparrowStudio.Core.dll, Newtonsoft.Json.dll and both Microsoft.Web.WebView2.Core.dll / Microsoft.Web.WebView2.WinForms.dll. Deploy those plus x64 WebView2Loader.dll and the existing sparrow_dotnet_native.dll beside the application. Retain LICENSE, LICENSE.txt (WebView2) and THIRD_PARTY_NOTICES.txt. Newtonsoft.Json is pinned to 13.0.1; WebView2 SDK to 1.0.3179.45 (net462-compatible assets). No packages.config changes are required for a legacy application.

Microsoft Edge WebView2 Evergreen Runtime must already be installed. Missing-runtime errors are explicit; the library does not install software. For an offline workstation, an administrator must deploy the x64 Evergreen standalone installer before running ImageAssist; the NuGet SDK and WebView2Loader.dll are not the browser runtime. Deploy Microsoft Visual C++ 2015–2022 Redistributable (x64) for the native Rust/MSVC engine and loader dependencies. Keep the existing ImageAssist native/Skia dependencies. No installer is downloaded or launched by this library. Its default profile is `%LOCALAPPDATA%/SparrowStudio/WebView2`, never the EXE directory; set UserDataFolder before showing to select another writable path.

All session creation, start and polling run off the UI thread. A UI timer updates elapsed time independently of incoming native events. Close requests cancel and keep the message loop alive until the sole RunAsync consumer completes. Direct Dispose during a solve is deferred until cancellation and native session disposal finish; callers must keep the WinForms message loop alive rather than terminate the process. Repeated Dispose after completion is safe.

## Security and ownership

HTML, CSS and JS are embedded resources assembled into one NavigateToString document below 2 MB. There are no external fonts, scripts, images or network calls. CSP denies network/frame/object/form access; host rejects resource requests, navigation, new windows, downloads and permission requests. Host objects, developer tools and browser shortcuts are disabled. Job names and labels use textContent, and geometry uses SVG DOM attributes; user data is not inserted as HTML.

Only messages from about:blank are accepted. All commands except Start retain the exact one-property contract `{type: ready|stop|cancel|apply|close}`. Start requires exactly `{type: "start", settings: {timeLimitSeconds: 10, sheetInitialSearchSeconds: 0.2, sheetInsertionWarmStartSeconds: 2, sheetCompressionSeconds: 2, sheetInsertionFailures: 1}}`. All five fields are required, with total explicitly null for automatic mode. The host strictly checks exact case-sensitive field names, numeric token types (integer for total/insertion/compression/failures, numeric for initial search), finite ranges and allowed total values before changing its cloned Job or creating any session. Unknown, missing, duplicated or invalid fields are rejected without starting. Browser validation is only an aid; no arbitrary Job or geometry update is accepted. NavigateToString may report its initial NavigationStarting URI as a data:text/html base64 document on this runtime; only the exact host-assembled document (or about:blank) is allowed once. Every later navigation and all frame navigation are denied. The committed page and message source remain about:blank. Result payloads from JavaScript are never read. Start is single-use, and apply is enabled only after native exit, no host error or discard, exact placement coverage and independent NestingSolver.Validate. Normal results still require Complete and no cancellation; only the explicit stopped snapshot path permits UserStopped after independent validation. CopyIndex is local to each board: coverage is checked against each SheetResult.Job, then per-Part quantities are summed against the original Job. Dispose the dialog after ShowDialog returns. Native session lifetime is held until RunAsync completes.

## ImageAssist

SparrowNestProgressDialog subclasses this preview. MainForm1 passes sparrow.Job and, only after Apply/OK, runs another independent Validate against progress.EffectiveJob (a detached clone of the actual solve Job with selected budgets) and SparrowNestOpt.AcceptResult. The public snapshot cannot mutate the private solve Job; the page can change only the five whitelisted budget fields, never geometry. The existing Operation.Execute/Undo and coordinate mapping remain unchanged. The legacy NestOpt path and native algorithm are not modified.

## Tests

The sibling winforms-smoke executable drives the real WebView2 page in an STA WinForms message loop. It checks readiness, solve snapshots, apply/cancel state and offline resource bounds. This is programmatic smoke coverage, not a claim of manual UI testing. `SparrowStudio.WinForms.Smoke.exe --contracts-only` runs managed reflection checks for malformed/unknown/range/type-invalid Start payloads without creating a session or opening a browser; it also checks effective budget values, null automatic deadlines and snapshot isolation. The full executable additionally edits the real WebView2 controls to 10 / 0.2 / 2 / 2, checks serialized host EffectiveJob and every native child Job setting, locks during/after execution, rejects a second Start, and retains every original stop/cancel/close/dispose scenario. Run the full smoke only after deploying the rebuilt native DLL that supports sheetInitialSearchSeconds; compiling against an old deployed DLL or passing contracts-only does not establish native parameter propagation.
